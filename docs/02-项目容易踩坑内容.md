> **TOTP/HOTP密码学部分本身标准公开(RFC4226/RFC6238)，算法实现难度不高；真正麻烦的不是算6位验证码，而是周边配套：本地加密存储、导入导出、迁移、移动端安全、备份格式**。

## ✅ 哪些部分容易实现

1. 密码学算法（TOTP / HOTP）

   - Base32 编解码（Secret是Base32，注意是RFC3548的Base32，不是Base64）

   - HMAC‑SHA1/SHA256/SHA512

   - TOTP时间步计算：`floor(unix_time / 30)`

   - HOTP计数器自增、数字截断取6‑8位验证码

   - otpauth:// URI解析（从二维码解析结果解析出 issuer, account, secret, period, digits, algorithm）

     > 这一块命令行工具写起来非常快，Go / Rust / Python 都有现成库。

2. **离线生成验证码** 完全不需要网络；只要本地存下secret，就可以计算。

## ⚠️ 真正有工作量、容易踩坑的部分（难点）

### 1. 本地加密存储（核心难点）

不能像FreeOTP一样直接明文存secret！

- 方案A：整体密码加密一个数据库文件（类似Aegis的vault，Ente Auth的本地库）

  - 选择加密：AES‑256‑GCM；由用户设置主密码，通过PBKDF2 / Argon2id派生密钥。
  - 所有OTP条目（secret、issuer、账号、参数）加密之后再落盘；内存中使用时才解密。
  - 注意：**不要直接拿用户密码当AES密钥；必须经过密钥派生函数加盐迭代**。

- 移动端额外坑：Android Keystore / iOS Keychain。可以把派生密钥存进系统安全芯片，防止root/jail之后直接扒数据库。

  > 命令行工具可以直接读写加密本地文件；APP还要对接系统密钥存储。

### 2. 导入 / 导出 / 迁移格式（没有统一国标！各家格式不一样）

这是最繁琐的地方：

1. **otpauth URI文本导入**：最简单，一行一个 `otpauth://totp/...`；可以导入导出纯文本（⚠️明文，不安全，仅临时迁移）

2. **Google Authenticator 迁移二维码 `otpauth‑migration://`** 这是谷歌私有的protobuf编码格式！**不是公开RFC标准**。很多开源项目单独逆向实现解析。想支持谷歌迁移就需要额外实现protobuf解码。

3. **Aegis备份格式（JSON+加密）** 自定义加密zip；有公开schema。

4. 2FAS / Ente Auth 各自私有备份格式

   > 现实：**不存在统一的加密交换格式**。自研工具一般两种路线：
   >
   > - 路线1：自家自定义加密备份格式（优先自家导入导出）；同时支持导入公开的otpauth URI；对谷歌迁移二维码做兼容。
   > - 路线2：只导出明文otpauth URI列表做迁移，警告用户该导出是明文，注意保密。

### 3. 二维码扫码识别模块

- 命令行：读取本地图片文件，调用ZXing/ZBar库解析图片得到otpauth字符串；无摄像头扫码。
- APP：调用摄像头实时扫描QR；权限、相机预览、对焦；相册图片识别。

### 4. UI（移动端APP）

- 条目列表展示、分组、搜索；刷新倒计时进度条（30秒倒计时动画）。
- 点击复制验证码到剪贴板；剪贴板自动清除（安全特性）。

### 5. 命令行 vs App 实现对比

| 模块          | CLI命令行工具(Go/Rust)             | 手机APP(Android/iOS)          |
| ------------- | ---------------------------------- | ----------------------------- |
| TOTP/HOTP算法 | ✅简单直接                          | 复用相同算法逻辑              |
| 加密存储      | 本地加密文件即可                   | 还要对接系统KeyStore/KeyChain |
| 扫码          | 仅读取本地二维码图片，无实时摄像头 | 摄像头实时扫码、相册识别      |
| 导入导出      | 优先自家加密备份 + otpauth uri文本 | 同样备份；剪贴板安全处理      |
| 倒计时UI      | 打印剩余秒数文本                   | 前端动画进度条                |
| 系统安全防护  | 基本不需要                         | 防root、防截屏、剪贴板清理    |

## 📦 技术选型建议

### 命令行工具（优先Rust）

- 密码库：rust‑crypto 实现HMAC‑SHA；Base32编解码；Argon2id/PBKDF2密钥派生；AES‑256‑GCM。
- QR解析：用纯 Rust 的 `rqrr` 读取图片解析二维码（不引入 C/C++ 依赖，见上方状态说明）
- 存储：单个加密文件保存全部OTP库；JSON作为内部结构，整体AES‑GCM加密落盘。
- 导出：①自家加密备份文件；②导出明文`otpauth://`文本（提示风险）；③支持解析谷歌迁移二维码导入。

### 移动端APP

- 跨端方案：Flutter，复用业务逻辑；底层密码学最好不要直接用dart纯库，可以调用Rust编译native库更稳妥。
- 存储：优先系统密钥库保护密钥；加密Vault文件。

## 🚨 安全上的坑，自研很容易忽略

1. **内存残留问题**：解密后的Secret在内存，如果处理不当，内存dump可以直接扒密钥；Rust相对更容易做内存擦除。
2. 导出明文备份一旦泄露，全部2FA直接失守；所以加密备份是硬性需求。
3. Google Authenticator迁移协议是逆向出来的，未来版本谷歌可能改动，存在兼容断裂风险。
4. 手机root之后，无论APP怎么做上层加密，如果系统被攻破，依然可以读取内存中的密钥；这是所有2FA App共同的局限。

## 📝 整体功能清单（自研需求清单）

**CLI + APP共同功能：**

1. 离线TOTP / HOTP 生成验证码；支持自定义 period、digits、sha1/sha256/sha512
2. 解析otpauth:// URI；从二维码图片识别URI导入账号
3. **本地加密保险库，主密码保护；密钥派生使用Argon2id**
4. 导入：otpauth uri文本；Google Authenticator迁移二维码导入
5. 导出：自家加密备份文件；可选导出明文otpauth文本（弹窗警告风险）
6. 条目管理：增加、删除、编辑、分组、搜索

**APP独有：**

- 摄像头扫码；倒计时进度条；一键复制验证码；剪贴板自动清空；生物识别解锁保险库。

> 总结：**算法层门槛低；真正工作量在于加密存储、备份迁移格式适配、移动端系统安全适配。** 市面上Aegis就是一个很好的参考开源项目，可以直接查阅它的仓库逻辑。
