## 项目文档规范



### 文档和注释

- 项目文档统一存储docs目录，按顺序标号命名中文文档
- 注释、日志内容统一使用中文，使用 UTF-8 无 BOM 编码
- 统一错误处理，所有错误信息都必须使用中文，禁止打印明文密码等敏感信息
- 及时更新文档
- SSH 推送github仓库（git@github.com:bliubiu/2fa.git）



#### CHANGELOG 规范

> 版本号类型说明：**CalVer（日历版本）**/**SemVer（语义化版本）**
>
> - CalVer 版本号格式：YYYY.MM.DD.MICRO
> - SemVer 格式：`主版本号Major.次版本号Minor.补丁号Patch[-可选标签 alpha|beta|rc]`

- **本项目采用双轨版本制。** 这是硬技术约束驱动的：`Cargo.toml` 的 `version` 字段必须能被 `semver` crate 解析，而 `2026.10.8.1` 这样的 CalVer 字符串会被直接拒绝。两条轨道各司其职，不可混用。
- **CalVer（主口径）**：格式 `YYYY.MM.DD.MICRO`（年.月.日.当日迭代号），用于 CHANGELOG 标题与 Git Tag
- **SemVer（包管理器口径）**：格式 `主版本号Major.次版本号Minor.补丁号Patch[-可选标签 alpha|beta|rc]`，用于 `Cargo.toml` 的 `version`。保持 `0.x`，表示 API 未稳定，对外正式发布前不升主版本号
- **CHANGELOG 标题格式**：`## [2026.10.08.0] - 0.1.0`（左为 CalVer 主口径，右为 SemVer 包管理器口径）
- 项目根目录建立 `CHANGELOG.md` 文档，单个文档随时间线推移逐渐变得臃肿，定期归档到 `docs/changelogs/` 目录
- **里程碑名不是版本号**。产品规划里的「M1 算法内核」「M2 保险库」等是里程碑标识，不参与版本号计算，也不得写入版本字段
- Tag 名称与 CalVer 版本号完全一致（如 `2026.10.08.0`），仅在稳定分支正式发布时创建，禁止随意打测试 Tag
- 修改 `Cargo.toml` 版本号时必须同步更新 CHANGELOG 顶部的 SemVer 值，二者不得脱节

### 注意事项

- 每次改动完成后，都必须创建一个对应的 Git commit，以便后续追踪和回滚。
- 每次改动后，都必须编写或更新相关测试，并在交付给用户前，确保所有测试和验证全部通过。



### 日志系统

支持多日志级别（DEBUG、INFO、ERROR）。**默认只输出到终端，不落盘**。

- **日志级别**：DEBUG、INFO、ERROR 三级，通过 `RUST_LOG` 环境变量或 `--log-level` 参数指定，默认 INFO
- **日志格式**：`[YYYY-MM-DD HH:MM:SS.SSS] [级别] [进程ID] [模块:行号] - 日志内容`
- **时间戳格式**：`YYYY-MM-DD HH:MM:SS.SSS` 本地时间，不含时区
- **终端输出**：默认且唯一默认输出目标，统一写入 stderr（保证 `2fa list --json` 这类管道输出不被污染）
- **文件输出**：**必须显式 opt-in**（`--log-to-file`）。路径使用平台数据目录约定——`%LOCALAPPDATA%\2fa\logs\`（Windows）、`$XDG_STATE_HOME/2fa/logs/` 或 `~/.local/state/2fa/logs/`（macOS/Linux）。**不使用「项目根目录/logs/」**，因为 CLI 是 PATH 上的单个二进制，没有项目根目录
- **文件命名**：`2fa-YYYYMMDD.log`，例如 `2fa-20261008.log`
- **轮转与保留**：按日期轮转，每日一个文件，保留 **7 天**（非 32 天），过期自动清理；提供 `2fa logs purge` 手动清理
- **日志内容**：统一使用中文，清晰记录操作行为、执行结果、错误信息，便于问题排查和审计

#### 脱敏策略（硬性规则，违反即为缺陷）

**第一优先级：禁止记录 OTP 密钥。** 本项目处理的是用户全部账号的访问凭据，日志落盘明文密钥会把一个内存残留问题升级为磁盘上永久的、免解密即可读取的副本。

禁止记录的内容：

- OTP 密钥（Base32 原文或解码后的字节，任何形式，包括 DEBUG 级别）
- 保险库密钥、封套密文、任何密钥派生值
- 主密码、恢复码
- 加密前后的保险库正文
- 完整的 `otpauth://` URI 与 `otpauth-migration://` 载荷（其中含密钥）

**该规则没有例外，包括 DEBUG 级别。** 实现方式是在类型层面把密钥包进 `zeroize::Zeroizing<T>` 并禁止其 `Clone`，配合一个会在 `Debug` 实现里固定输出 `«已隐藏»` 的包装类型，使其在任何日志级别下都不可能被格式化打印。

用户输入的账号、邮箱、服务商名称可以记录——它们不是凭据。但完整手机号、身份证号仍按常规脱敏规范处理。




## 语言强制规则（必须严格遵守）

1. 所有回复、解释、对话、说明必须**全程使用中文**，禁止出现任何英文。
2. 不允许切换语言，全程保持纯中文交互。
3. 解释、说明、思考过程、总结、步骤描述，全部使用中文。
