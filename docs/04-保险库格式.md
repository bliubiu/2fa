# 保险库文件格式规格

本文档描述 2FA 保险库文件（单文件 JSON 加密保险库，见 [`docs/adr/0001`](./adr/0001-单文件-json-保险库.md)）的字节级布局、认证纪律与兼容性规则。格式定义以 [`crates/2fa-core/src/vault/`](../crates/2fa-core/src/vault/) 实现为准。

## 总览

文件由**明文头部**与**加密正文**两部分组成。明文头部整体作为正文 AES-256-GCM 的 AAD（Additional Authenticated Data）参与认证——篡改头部任意字节必然导致正文解密失败。

```text
[头部（明文，整体作为正文 GCM 的 AAD）]
  magic            "2FAVLT\0"（7 字节）
  schema_version   u16 大端
  envelope_count   u8（封套数量）
  封套列表         envelope_count × 78 字节
  nonce            12 字节（正文 GCM 专用，每封存一次重新随机）
[正文（密文）]
  JSON 明文的 AES-256-GCM 密文（含 16 字节认证标签）
```

最小合法文件长度 = 固定头部 22 字节 + 0 封套 + 16 字节标签 = 38 字节。

## 认证纪律

| 层级 | AAD 覆盖范围 | 意义 |
|---|---|---|
| 正文 GCM | **整个头部**（含 magic 全部字节、schema_version、全部封套、正文 nonce） | 篡改头部任意字节 → 正文认证失败，文件不可信 |
| 封套 GCM | 仅本封套的 `salt[16] + kdf_version[2]` | 重写任一封套不影响其他封套的认证；`kdf_version` 在 AAD 内不可被降级篡改 |

失败语义严格区分两类文案：「认证失败（凭据不正确或被篡改）」与「数据损坏（布局不符）」。

## 封套布局（78 字节 × n）

封套 = 一段凭据（主密码或恢复码）对 32 字节保险库主密钥（`VaultKey`）的加密封装：

```text
salt          16 字节（KDF 盐，CSPRNG）
kdf_version   u16 大端（KDF 版本查表，见下）
nonce         12 字节（封套 GCM 专用）
ciphertext    48 字节 = 32 字节主密钥 + 16 字节 GCM 认证标签
```

典型保险库含 2 个封套：主密码封套 + 恢复码封套。两个封套解出**同一个主密钥**，凭据不同、盐不同、密文不同。

### KDF 版本查表

| 版本 | 算法 | 参数 |
|---|---|---|
| v1 | Argon2id | 19 MiB / t=2 / p=1 |

静态查表，不允许运行时自定义参数；未知版本明确报错，**绝不降级尝试**。解锁时被使用封套的 `kdf_version` 低于当前版本会自动升级（同一凭据重新封存 + 按新头部重算正文，主密钥与条目明文不变），升级前原始字节备份 `.bak`。

## 正文 JSON schema（schema_version = 1）

正文为 UTF-8 JSON，字段：

```json
{
  "schema_version": 1,
  "created_at": 1700000000,
  "entries": [
    {
      "id": "0194…（UUID v7，时间有序）",
      "issuer": "GitHub",
      "account": "alice",
      "secret": "JBSWY3DPEHPK3PXP（Base32 文本）",
      "algorithm": "SHA1",
      "digits": 6,
      "period": 30,
      "tags": ["工作", "代码"]
    }
  ]
}
```

- `algorithm` 存大写规范名：`SHA1` / `SHA256` / `SHA512`
- `digits` 仅 6 或 8；`period` 单位秒（正整数）
- `(issuer, account)` 归一化（大小写与空白不敏感）用于同标识判定，但允许同组多条目并存（密钥换绑场景，用户显式选择）
- `secret` 的序列化直接引用零化缓冲，反序列化产生的中间副本立即清零（`SecretKey` 禁 `Clone`/`Copy`，`Debug` 固定输出 `«已隐藏»`）

## schema 迁移链（兼容性规则）

- `schema_version`（头部与正文各一份）**单调递增**，与 KDF 版本相互独立
- 迁移为逐级纯函数：每级迁移的入参必须是**恰好该级版本**（防跳级），无迁移路径的版本明确报错、绝不静默
- 低版本程序读到高版本文件：明确报错提示升级，不部分加载、不触碰文件
- 迁移前原始字节备份 `.bak`，回写走原子写入，中断可回滚
- **禁止用 `serde(default)` 做格式兼容**——字段重命名、新增必填字段、嵌套结构改变都会静默丢数据，必须走显式迁移链

## 写盘纪律

### 原子写入（四步，缺一不可）

1. 写临时文件（同目录）
2. `fsync` 临时文件
3. `rename` 到目标路径
4. `fsync` 父目录

少一步就有断电损坏窗口；失败不伤目标并清理临时文件。

### 文件锁（跨进程）

`O_EXCL` 独占创建锁文件 + 锁文件内记录 PID 判活 + mtime 阈值接管（持有者崩溃后由后来者按阈值收养）；Windows 附加 `DELETE_ON_CLOSE` 使崩溃残留锁文件自清。全程无 `unsafe`（`LockFileEx`/`flock` 等 FFI 与 `unsafe_code = "forbid"` 冲突，故不采用）。

## 备份纪律

- **加密备份**（`export backup` / `import`）是保险库文件的**字节级拷贝**：无转换层、无需解锁，恢复后凭据即备份文件中的凭据。备份导入采用只读验证（`unlock_readonly` 不写文件、不触发 KDF 升级），确认后才覆盖写入
- 任何变更操作（解锁升级、条目增删改、恢复码轮换、迁移）回写前都会将原始字节备份 `.bak`
- 明文导出是危险出口：仅 `export plain`，须通过四道门槛（交互确认条目数 / `--yes`、路径必选、首行警告注释、完成即提示删除）

## 防呆

- 错误魔数报「这不是 2FA 保险库文件」（区别于密码错误的「认证失败」）
- 每条 CLI 命令回显当前保险库绝对路径与解析来源（`--vault` / CWD 下 `.2fa/` / 平台惯例），防止用户在错误的保险库上编辑
- 明文头部中的 `kdf_version` 不可降级篡改（封套 AAD 覆盖）；正文版本比程序新时报错提示升级
