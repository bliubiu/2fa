## M1 算法内核

### M1-1 Base32 编解码

- 实现 RFC 4648 无填充变体的编码与解码
- **宽容解析**（真实世界的密钥经常不规范）：去除空白与 `=` 填充、自动补齐填充后再解码、接受小写输入
- 拒绝非法字符与非法长度，返回明确的中文错误

**测试**：RFC 4648 测试向量全绿；容错用例表（带空格、带填充、小写、多余填充、非法字符、长度截断、只含 `=`、空串）。

### M1-2 TOTP 计算内核

- `TOTP(密钥, 计数器, 算法, 位数) -> 验证码`，纯函数，不读系统时间
- 动态截断（RFC 4226 §5.3）：取 HMAC 末字节低 4 位为偏移，截取 4 字节后对 `10^位数` 取模
- 算法枚举：`Sha1` / `Sha256` / `Sha512`
- 位数：`6` / `8`；非法位数立即报错，不做静默截断
- **时间步由调用方以计数器形式传入**，不在本层读时钟——这是为了让测试向量可以直接喂固定值

**测试**：RFC 4226 Appendix D 全部 8 组向量（TOTP 内核即带计数器的 HOTP，直接适用）；RFC 6238 Appendix B 全部向量（6 个时间点 × SHA1/SHA256/SHA512，其中 SHA256 对应 32 字节 seed、SHA512 对应 64 字节 seed，**不同长度**，这是最常见的实现错误）；边界计数器 0 与 `u64::MAX`；`period` 为 30/60/15 时的正确取整。

### M1-3 计数器换算

- `计数器 = floor(Unix 时间戳 / period)`，使用整数除法，禁止浮点
- 校验 `period >= 1`；`period == 0` 直接报错防除零
- 剩余秒数 `= period - (时间戳 mod period)`

**测试**：时间戳恰好落在周期边界（`0` / `29` / `30` / `31`）；负数时间戳；超大时间戳。

### M1-4 Steam Guard

- HMAC-SHA1，5 位，自定义字母表 `23456789BCDFGHJKMNPQRTVWXY`
- 复用 M1-2 的动态截断，替换最后一步的取模与字符映射

**测试**：用 Aegis 与 steamguard-cli 的已知实现交叉验证同一密钥同一时间窗的输出必须一致（经核实 FreeOTP 仅实现标准 HOTP/TOTP，不支持 Steam 自定义字母表，不能作为验证对象）。**无官方测试向量，交叉验证是唯一依据**，验证样本来源需记录在测试注释里。

### M1-5 otpauth URI 解析

- 解析 `otpauth://totp/<label>?secret=&issuer=&algorithm=&digits=&period=`
- **issuer 冲突统一**：路径前缀与 query 不一致时**以 query 为准**并记录警告；两者仅一方存在时用存在的一方
- label 为 `服务商:账号` 形式时拆分；无冒号时整个 label 作为服务商
- 百分号解码（服务商名与账号常含 `@`、空格、中文）
- `algorithm` 默认 `SHA1`；`digits` 默认 `6`；`period` 默认 `30`
- **未知参数一律忽略，不报错**（真实 URI 中充满各家自定义参数）
- 序列化方向：`条目 -> otpauth URI`，供明文导出使用

**测试**：标准样例；issuer 冲突样例（`GitHub` vs `GitHub2`）；中文服务商名；label 无冒号；label 含多个冒号；未知参数；缺 `secret`；非法 `period`；空字符串；超长输入。

## M2 保险库

### M2-1 保险库密钥类型与随机源

- 定义 `VaultKey`（`Zeroizing<[u8; 32]>`），**禁止 `Clone`**，`Debug` 固定输出 `«已隐藏»`
- 定义 `SecretKey`（Base32 文本的零化包装），同样禁止 `Clone`/`Copy`
- 所有随机数来自 `getrandom`（操作系统 CSPRNG），**禁止任何伪随机或退化实现**

**测试**：连续生成 100 个密钥无重复；`Debug` 输出不含密钥片段（编译期无法验证部分用 `trybuild` 或人工 review 保证）。

### M2-2 KDF 版本查表

- `kdf_version -> 参数` 静态表，当前 v1 = Argon2id / m=19456 KiB / t=2 / p=1
- `derive(密码, 盐, kdf_version) -> Zeroizing<[u8; 32]>`
- 未知版本返回明确错误，不回退到默认参数

**测试**：v1 派生结果长度正确；同一输入可复现；不同盐产出不同结果；未知版本报错。

### M2-3 封套读写

- `封套 = (salt[16], kdf_version, ciphertext)`，`ciphertext = AES-256-GCM(KEK, vault_key, aad=本封套的 salt 与 kdf_version 字节)`
- **封套 AAD 只覆盖本封套自身**，不含另一封套与全局字段——重写任一封套都不影响另一封套的认证
- 重写封套须由上层连带按新头部重算正文密文（条目明文不变），见 M2-9
- 写封套、读封套、解封（成功后归零 KEK）
- 失败时区分「认证失败（密码错）」与「数据损坏」两种错误文案

**测试**：正确密码可解；错误密码必定认证失败；篡改密文任一字节必被拒；篡改盐必被拒；篡改封套内 `kdf_version` 必被拒；重写主密码封套后恢复码封套仍可正常解封（反之亦然）。

### M2-4 文件格式与 AAD 组装

- 明文头部：`magic("2FAVLT\0")` + `schema_version` + 封套列表（各含盐与 `kdf_version`）+ `nonce`
- **整个头部（含 magic 的全部字节）作为正文 GCM 的 AAD** 参与认证
- 正文 = `AES-256-GCM(vault_key, nonce, json, aad=头部)`

**测试**：往返一致；篡改 magic/`schema_version`/封套（含其盐与 `kdf_version`）/`nonce` 任一字节必被拒；错误 magic 给出「这不是 2FA 保险库文件」而非「密码错误」。

### M2-5 保险库正文与条目模型

- JSON 正文：`{ schema_version, created_at, entries: [...] }`
- 条目：`{ id, issuer, account, secret, algorithm, digits, period, tags: [] }`
- `id` 使用 UUID v7（时间有序，便于人工排序与调试）；不得用随机 v4（不利于排查问题）与自增整数（多设备合并冲突）
- 条目按 `(issuer, account)` 归一化（大小写与空白不敏感）：同标识多条目**允许并存**（同站换绑密钥是合法场景），但 add/edit/import 遇到同标识时必须显式提示并由用户选择，不得静默创建或静默拒绝

**测试**：序列化往返字段级一致；`secret` 字段自定义序列化，序列化后立即清零中间缓冲；`(issuer, account)` 归一化用例。

### M2-6 原子写入与文件锁

- 原子写入：临时文件 → 写 → fsync 文件 → rename → fsync 父目录
- 文件锁：advisory lock 独占；残留锁用 PID + 进程起始时间校验后接管
- Windows 使用 `LockFileEx`，Unix 使用 `flock`

**测试**：写入中途 kill 进程后原文件完好；两个进程并发写只有一个成功，另一个得到明确中文提示；残留锁被正确识别为失效。

### M2-7 内存保护

- 全部密钥类型 `Zeroizing` 包装，禁 `Clone`
- 尽��而为：Unix `mlockall(MCL_CURRENT|MCL_FUTURE)` + `setrlimit(RLIMIT_CORE, 0)`；Windows `VirtualLock` + `SetErrorMode`
- **失败只警告不中断**，向 stderr 输出中文提示后继续

**测试**：在无 `CAP_IPC_LOCK` 的受限环境下启动仍可用；解锁耗时以计时测试对照 PRD 性能指标（`2fa bench` 于 M3-7 落地后复核）。

### M2-8 schema 迁移链

- `schema_version` 单调递增；`v1 -> v2 -> ... -> 当前` 逐级纯函数迁移
- 迁移前生成 `.bak`；迁移走临时文件 + rename（可中断）
- 低版本程序读高版本文件时明确报错并提示升级，**不尝试部分加载**

**测试**：构造 v1 文件，迁移后内容语义等价；迁移链每级单独可测；迁移中断后原文件完好；`.bak` 可用于回滚。

### M2-9 KDF 自动升级

- 解锁成功后若某个封套的 `kdf_version` 低于当前版本，后台重写该封套，并按新头部重算正文密文（条目明文不变）
- 重写失败不阻断解锁，仅警告

**测试**：v1 文件在当前版本下解锁后文件被升级为当前版本，且条目内容未变；两封套 `kdf_version` 不一致时可正常解锁。

## M3 CLI 骨架

### M3-1 参数解析与路径解析

- `--vault <路径>` > CWD 下 `.2fa/vault.json` > 平台惯例路径
- `2fa init [--project]`：创建新保险库并执行首次设置流程；`--project` 在当前目录创建 `.2fa/vault.json`，对已存在的保险库拒绝初始化并明确报错
- **每条命令回显当前保险库绝对路径与来源**（`--vault` / `项目内` / `平台惯例`）
- 首次在 CWD 创建 `.2fa/` 时显式提示
- `$XDG_DATA_HOME` 未设置时回退 `~/.local/share`

**测试**：三种来源各自的路径解析用例；`$XDG_DATA_HOME` 未设置时的回退；路径回显存在于每条子命令的输出中；`init` 在两种位置创建正确，对已有保险库重复 `init` 被拒绝。

### M3-2 REPL 框架

- `rustyline` 驱动的交互循环，提示符 `2fa> `
- 空闲超时自动锁定：默认 5 分钟，`--idle-timeout` 可配置
- `lock` 命令立即锁定并归零内存
- 进程退出（正常退出 / Ctrl-C / panic）无条件归零

**测试**：模拟空闲超时后自动锁定；`lock` 后再次操作需重新解锁；Ctrl-C 后无残留内存。

### M3-3 单次命令模式

- `--stdin-password` 从 stdin 读主密码（供脚本与管道使用）
- 每条命令独立进程，执行完即退出并归零
- 保证 stdout 只有命令输出，日志全部走 stderr

**测试**：`2fa --stdin-password list` 输出可被管道解析；退出码正确（成功 0、密码错非 0）。

### M3-4 条目 CRUD 与展示

- `add` / `edit` / `del` / `show` / `list` / `find` / `status`
- 列表展示：服务商、账号、当前验证码、剩余秒数
- **禁止在终端展示密钥**（除显式 `show <id>` 命令，且需二次确认并提示这是明文）
- 交互式添加遇到归一化后同 `(issuer, account)` 的条目时，提示已存在并由用户选择：覆盖、并存或取消

**测试**：CRUD 全流程用例；重名条目提示；`show` 的确认流程。

### M3-5 watch 倒计时

- 循环刷新验证码与进度，Ctrl-C 退出
- 使用单调时钟对齐周期边界，避免刷新漂移
- 刷新时不重复打印滚动日志（终端控制）

**测试**：连续运行 3 个周期，验证码在正确的时间点切换；无漂移累积。

### M3-6 恢复码恢复与轮换

- `recover` 交互式提示输入恢复码（不经行内参数，避免进入 shell 历史与终端回滚），解锁成功后强制进入轮换流程：生成新恢复码、重写恢复码封套、打印并强制确认已保存
- 轮换完成后旧恢复码作废（其封套已被重写）；轮换中断（进程被杀）时原文件完好，旧码仍可用

**测试**：轮换后旧码解封必失败、新码成功；轮换中断后旧码仍可解封；轮换只触及恢复码封套与正文认证，条目明文不变。

### M3-7 日志与辅助命令

- `--log-level`（DEBUG/INFO/ERROR，默认 INFO）与 `RUST_LOG`；日志默认仅 stderr，不落盘
- `--log-to-file` 显式开启文件日志：路径遵循 [`00-项目文档格式.md`](./00-项目文档格式.md) 日志规范，按日轮转、保留 7 天自动清理
- `2fa logs purge` 手动清理过期日志
- `2fa bench`：报告解锁耗时（含 Argon2id）与单次 TOTP 计算耗时，供 M2-7 与 M6-4 复核

**测试**：默认运行无任何文件落盘；`--log-to-file` 后文件生成且内容经检索确认无密钥、无密码、无 `otpauth` 载荷；`logs purge` 清理过期文件；`bench` 输出可读且数值合理。

## M4 导入导出

### M4-1 otpauth 文本导入

- 一行一条 `otpauth://`，忽略空行与 `#` 注释行
- 单行解析失败不中断整批，逐条报告成功与失败
- 重复条目（归一化同标识且密钥相同）默认跳过并提示；同标识不同密钥时由用户选择：覆盖、并存保留或跳过

**测试**：含注释行的文件；部分条目损坏的批次；重复条目。

### M4-2 Google 迁移二维码解析

- `otpauth-migration://offline?data=<base64>` → base64 解码（用 `data-encoding` 的 BASE64，不新增依赖）→ 手写 protobuf varint 解析
- 按社区逆向 schema 解析（字段号固定）：`MigrationPayload { repeated OtpParameters otp_parameters=1; int32 version=2; int32 batch_size=3; int32 batch_index=4; int32 batch_id=5 }`；`OtpParameters { bytes secret=1; string name=2; string issuer=3; algorithm=4（枚举）; digits=5（枚举）; type=6; counter=7 }`
- `name` 按「服务商:账号」拆分（与 M1-5 的 label 规则一致）；`type=2`（TOTP）正常导入
- **`type=1`（HOTP）条目拒绝导入**并给出明确中文提示，绝不静默当作 TOTP 解析（会产出错误验证码）
- 载荷不含 `period` 字段：一律按 30 秒导入（与 Google Authenticator 行为一致），条目可事后 `edit`
- 多批次导出（`batch_size > 1`）逐张导入，进度可见
- **不引入 `prost`**：schema 极简，手写 varint 解析约 150 行且无构建期代码生成步骤
- 解析后**必须提示用户立即删除 Google Authenticator 中的原始迁移数据**（该载荷内密钥为明文）

**测试**：真实迁移二维码样本作为测试固件（样本来源记录在注释）；字段缺失、未知字段、类型错误、截断 varint、非法 base64、超大 payload；HOTP 条目被拒；与 Aegis 导入同一二维码的结果逐字段比对（经核实 FreeOTP 不支持 `otpauth-migration://` 导入，不能作为验证对象）。

### M4-3 加密备份导出与导入

- 导出 = 保险库文件字节级拷贝（**无转换层**）
- 导入前显式确认覆盖当前数据；导入后若 `schema_version` 较老自动走迁移链
- 导入后校验条目数与备份时的条目数一致，不一致时警告

**测试**：导出→清空→导入 往返后条目级完全一致；导入老版本备份自动迁移；条目数不一致时正确警告。

### M4-4 明文 otpauth 导出（危险出口）

**四道门槛，缺一不可**：

1. 二次确认：要求输入当前条目数或指定确认词
2. 必须显式指定输出路径（不提供默认路径，杜绝「随手存到桌面」）
3. 文件首行写入中文警告注释（`#` 开头，导入时被忽略）
4. 导出完成后立即提示用户删除该文件，并说明它未受任何加密保护

**测试**：四道门槛各自生效；未通过确认时文件不落盘；写入的警告注释能被自家导入器正确忽略。

## M7 CLI 增强

> 依据 PRD 第 10.1 节。前置：M0–M6 已完成（Tag `2026.10.10.0`）。

### M7-1 `code` 子命令

- `2fa code <前缀>`：解锁 → 按前缀定位条目 → stdout 输出 `验证码 剩余秒数`（空格分隔，供脚本取第一列）
- 前缀歧义时列出候选 ID 与标识后退出非 0，与既有交互一致；找不到时明确报错
- 剩余秒数由 CLI 取系统时间后经 `domain::counter` 换算，core 不读时钟（约束不变）

**测试**：输出格式（可被管道截取）；前缀歧义报错且列出候选；条目不存在；`--stdin-password` 管道全链路；剩余秒数与 `list` 一致。

### M7-2 剪贴板集成

- 引入 `arboard`（依赖决策见 PRD 10.1），`code --copy` 将验证码写入系统剪贴板
- 剪贴板打开失败（无头环境 / Wayland 未连接等）给出明确中文错误，不影响验证码本身输出
- 复制成功后输出提示「已复制到剪贴板（注意剪贴板残留）」；CLI 进程退出后不做定时清除（无法实现），GUI 端负责 30 秒自动清除

**测试**：复制失败路径的错误文案；无显示环境降级行为；Windows 实机手工验证。剪贴板内容断言不纳入自动化（平台差异大），以实机验证为准。

### M7-3 `qr` 子命令与 core 二维码编码

- core `qrcode` 模块新增 `encode_png(uri: &str) -> Result<Vec<u8>, _>`：`otpauth://` URI → PNG 字节。引入 `qrcode` crate（纯 Rust 编码器），PNG 编码复用已有 `image`
- URI 由 `domain::otpauth::to_uri` 从条目序列化生成（含 issuer、algorithm、digits、period）
- CLI `2fa qr <前缀> --out 路径.png`：门槛对齐 `show`（交互确认 / `--yes`）；输出完成后提示「图片内含明文密钥，使用后立即删除」
- 不覆盖已存在文件（`--out` 指向已有文件时报错），防止误覆盖

**测试**：生成的 PNG 用 `rqrr` 解码回原 URI（往返闭环，URI 逐字符一致）；含中文 issuer / 特殊字符的 URI；拒绝对已存在文件写入；未确认时不落盘；输出文件可被 Aegis 实机扫入（记录于测试注释）。

## M8 GUI 骨架

> 依据 PRD 第 10.2 节。技术栈：Tauri 2 + React + TypeScript + Zustand + Vite。`2fa-core` 为 Rust 依赖，不经过网络层。

### M8-1 Tauri 工程接入 workspace

- 建 `app/src-tauri`（Rust 壳，crate 名 `two-fa-app`）与 `app/src`（React），workspace 成员加入 `app/src-tauri`
- Tauri 配置：窗口标题「2FA 验证器」、默认尺寸、release 禁用 devtools、不加载远程内容
- `app/src` 用 Vite + React + TypeScript 模板，`pnpm` 管理；Tauri `beforeDevCommand`/`beforeBuildCommand` 接 Vite

**验收**：`cargo build` 全 workspace 通过；`pnpm tauri dev` 启动显示窗口空白页；`cargo clippy`/`fmt` 覆盖新 crate。

### M8-2 Tauri commands 与会话状态

- Rust 壳持有会话状态（保险库密钥在内存，core 类型零化）；commands：
  - `unlock(主密码)` → 状态/条目数；`lock()`；`status()` → 路径、来源、条目数、KDF 版本
  - `list_entries()` → `[{id, issuer, account, code, remaining_secs, ...}]`（时钟由壳取系统时间传入 core）
  - `get_code(id前缀)` → 验证码 + 剩余秒数
- 所有错误以带中文消息的 `Result` 返回给前端；日志走 stderr 且遵守脱敏规范

**测试**：Rust 侧单元测试（命令函数签名、错误映射）；前端 mock 通信。

### M8-3 前端骨架：解锁屏与列表实时倒计时

- Zustand 会话 store：`locked / unlocked` 状态机；解锁失败错误展示
- 条目列表页：服务商、账号、验证码、剩余秒数；每秒 tick 刷新，周期边界切换验证码
- 主密码输入组件：`type=password`，不进任何日志/持久化

**验收**：解锁后列表每秒刷新且周期边界验证码正确切换；与 CLI `list` 输出逐条一致。

### M8-4 自动锁定与剪贴板清除

- 空闲超时（默认 5 分钟，可配置）触发锁定：清空前端状态 + 后端密钥归零，回到解锁屏
- 复制验证码到剪贴板后 **30 秒自动清除**（仅当剪贴板内容仍为该验证码时清除，避免误清用户后续复制的内容）
- 锁定动作同步清除剪贴板计时器

**测试**：超时锁定（缩短超时验证）；复制后 30 秒剪贴板变空；复制其他内容后不被误清。

## 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| Steam Guard 无官方向量 | 算法可能静默错误，用户看到错验证码 | 与 Aegis/steamguard-cli 交叉验证（M1-4）；样本来源写入注释 |
| GA 迁移协议被谷歌改动 | 用户无法从 Google Authenticator 迁入 | 明确告知这是逆向兼容；失败时给出「用 otpauth 文本手工导入」的降级路径 |
| 恢复码用户未保存 | 仍会丢数据 | 首次设置强制确认；提供随时可查看的提示命令；文档反复强调 |
| 锁页在受限环境失败 | 安全降级但功能可用 | 已定为尽力而为 + 警告；实测解锁耗时写入性能报告 |
| 二维码解析器 CVE | 畸形图片导致崩溃或内存问题 | 输入上限 + fuzz（M5-3） |
| 格式演进遗漏旧字段 | 静默丢数据，字段级丢失极难排查 | 严格迁移链（M2-8），禁止 `serde(default)` 隐式容错 |
