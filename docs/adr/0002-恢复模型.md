# 恢复模型：主密码 + 强制恢复码，无找回密码、无云同步

保险库密钥是一把随机生成的 32 字节对称密钥，用两个独立的封套加密保存：主密码封套（Argon2id 从主密码派生密钥加密密钥解开）与恢复码封套。任一封套都能解封同一把保险库密钥。首次设置主密码时强制生成恢复码与一份加密备份，用户未确认已保存则不允许进入主界面。

## 为什么没有「找回密码」

产品定位是完全离线、无服务器（PRD §2）。任何「输入邮箱重置」都需要服务端，也就放弃了隐私优先这一唯一的差异化理由。可选的其他路——云同步、设备绑定密钥——都会带来同一个问题：它们让「离线、无上传任何数据」这句话不再成立。

## 为什么强制恢复码而不是只靠备份文件

纯靠用户主动导出的备份文件听起来更简单，但它把 100% 的希望压在「用户真的导出了」上。真实世界里总有人不导出，然后某天真的丢了主密码，于是 50 个账号永久失守——而且这个错误不可逆、不可挽回，用户会认为是我们把他们的密钥弄丢的。恢复码是唯一一条**不依赖用户提前做对某件事**的兜底路径，代价仅仅是首次设置时多一步。

## 为什么强制而不是提醒

因为「提醒」在实践中的转化率接近于零。如果恢复码可以跳过，总有人会跳过，然后总有人在需要它的时候发现它不存在。把它做成进入主界面的硬门槛，是用一次性的 UX 摩擦换取永久的数据安全。

## 后果

- 恢复码必须是高熵随机串（单枚，而非用户自选），否则它会被弱口令字典攻破，等于没有第二把钥匙。
- 恢复码校验必须恒定时间，避免时序侧信道泄露正确位数。
- 改主密码只重写主密码封套，不触及保险库密钥与条目内容——因此不需要 PRD §3.2 里那条「改密码无需重加密全部数据」的特例机制，两条封套并存本身就解决了它。
- 生物识别属 V1.1 GUI 范畴的设备本地第三层包裹，只影响解锁路径，不改变本 ADR 的密钥语义。
- 恢复码为单枚高熵随机串，与「恰好两个封套」的封套模型一一对应。
- 恢复码用后轮换：用其成功恢复后必须强制生成新恢复码并重写恢复码封套，旧码作废——这是「一次性」语义的落点，也覆盖恢复码在恢复过程中可能暴露的场景。
